## Summary (Granola AI notes)

### Protocol Stack and Encapsulation

- Five-layer model: Application, Transport, Network, Link, Physical
- Each layer treated as a black box: receives input, adds a layer-specific header, passes output down
- PDU (Protocol Data Unit): the output of each layer after header is added
  - Transport layer output: segment
  - Network layer output: datagram
  - Link layer output: frame
- Encapsulation: going down the stack, adding headers, growing packet size
- Decapsulation: going up the stack at the destination, each layer strips only its own header

### Devices, Sockets, and Addressing

- Devices operate at different layers:
  - Switch: Layer 2 (processes up to link layer only)
  - Router: Layer 3 (processes up to network layer)
  - End-user computer: Layer 7 (full stack)
- Application layer is the top layer users interact with (HTTP, email, DNS, streaming)
- Socket: the API/interface between an application process and the protocol stack below
  - OS controls everything below the socket; developers only manage the application layer
  - Two socket types:
    - UDP (datagram socket): connectionless, fast, less reliable
    - TCP (stream socket): connection-oriented, reliable, slightly slower
- Identifier = IP address + port number
  - IP address: identifies the host/device
  - Port number: identifies the specific process on that host
  - Well-known ports: HTTP = 80, mail = 25; others dynamically assigned

### Application Requirements and Quiz Notes

- Different apps have different transport needs:
  - File transfer, email, web: require reliability, not speed-sensitive → TCP
  - Real-time audio/video, interactive games: speed-sensitive, tolerate some loss → UDP
  - Streaming video: uses TCP
- Client-server vs. peer-to-peer architectures:
  - Client-server: server always on with fixed IP; clients dynamic, on/off
  - P2P: no fixed infrastructure; peers act as both client and server
