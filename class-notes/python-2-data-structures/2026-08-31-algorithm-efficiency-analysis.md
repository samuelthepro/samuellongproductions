## Summary (Granola AI notes)

### Algorithm Analysis vs. Program Analysis

-   Goal: compare algorithms, not programs, to avoid hardware/language/OS noise
-   Program performance varies by hardware, language, compiler, and OS; algorithm analysis abstracts all of that away
-   Two cost dimensions: time and space
    -   Space historically mattered more; now mostly focused on time
    -   Time measured using Python’s `time` library: record start, record end, subtract

### Successive Addition vs. Closed Form (Demo)

-   Two algorithms for summing consecutive integers from 1 to n
    -   Naive: loop-based successive addition (accumulator starts at 0, iterates 1 to n)
    -   Clever: closed form formula: `n * (n + 1) / 2`
-   Tested with n = 1,000 / 10,000 / 100,000 / 1,000,000
    -   Successive addition: linear trend visible on scatter plot, time scales with n
    -   Closed form: all runs land at ~E-7 seconds regardless of n; plot looks flat/noisy
-   Noise in closed form plot explained by background OS scheduling, not the algorithm
    -   Averaging over many runs would produce a horizontal line
    -   Illustrates why empirical timing alone is unreliable: use algorithm analysis instead

### Big O Notation

-   Big O = worst-case asymptotic time complexity; written O(f(n))
-   Key rules:
    -   Drop constants: O(15n) = O(n)
    -   Drop lower-order terms: O(15n² + 45n) = O(n²)
    -   Dominant term is the one that grows fastest as n → ∞
-   Assignment statements counted as 1 step by convention
-   Successive addition example: T(n) = 1 + n → O(n)
-   Closed form example: fixed number of arithmetic ops → O(1)

### Complexity Classes (Best to Worst)

-   O(1): constant time, best possible
-   O(log n): logarithmic, second best
-   O(n): linear, third best
-   O(n log n): log-linear, best achievable for general-purpose sorting
-   O(n²), O(n³): quadratic/cubic, significantly worse
-   O(2ⁿ), O(n!): exponential/factorial, extremely inefficient
-   Other notations (Ω, Θ, little-o) exist but won’t be used in this class
    -   Big Omega = best case (often trivial, e.g. O(1) if first element matches)
    -   Big Theta = tight bound; skipped for now
    -   Focus stays on Big O (worst case) throughout the course
