## Summary (Granola AI notes)

### Big O Notation and Asymptotic Complexity

- Focus of the course: time complexity (not space), expressed in Big O notation
- Only the dominant term matters as N grows arbitrarily large
  - Constants and lower-order terms are dropped
  - Multiplicative factors (e.g. 3n, 100n²) are irrelevant
- Complexity order, fastest to slowest:
  1. O(1): constant time
  2. O(log n): logarithmic
  3. O(n): linear
  4. O(n log n): linearithmic
  5. O(n²), O(n³): polynomial
  6. O(2ⁿ), O(n!): exponential/factorial

### Time Function Construction

- Convention: each assignment statement counts as 1 unit of time
- A standard for loop over n iterations costs n+1 units (n iterations + 1 final check)
- Nested loops multiply: two nested loops over n each yield n(n+1) inner steps, simplifying to O(n²)
- Worked example: 4n² + 5n + 6 simplifies to O(n²), dominant term wins
- Step size in loops: a loop stepping by 2 runs n/2 times, but the ½ factor is dropped, still O(n)
- Triple-nested loops: O(n³); inner loop over a fixed constant (e.g. 20): still O(n), constant absorbed

### Logarithmic Time and While Loops

- Halving the loop variable each iteration (integer division by 2) produces O(log n)
  - Progression example: 10 → 5 → 2 → 1 → 0, only \~log₂(n) steps
  - Contrast: doubling work each step would be O(2ⁿ); halving is the inverse
- Logs in this class are implicitly base 2 (base rarely matters asymptotically)
- Binary search previewed as the canonical log n algorithm
  - Ordered list: cut in half each step, guaranteed to find target in O(log n)

### Python List Performance

- Append and pop (no argument): O(1), deliberately optimized as the most common operations
- Insert and concatenation (+): O(k), must shift elements, avoid where possible
- Index access and index assignment: O(1), independent of list size
- in operator (contains check): O(n), scans from start to end in worst case
- Slice: roughly O(slice size), effectively linear
- Reverse: O(n)
- Sort (built-in): O(n log n), highly optimized; always prefer the built-in over a custom sort
- Practical note: same Big O class doesn’t mean same real-world speed
  - List comprehension \~2x faster than append loop
  - list(range(n)) is by far the fastest way to generate a numeric list
